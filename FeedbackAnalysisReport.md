### high · Pipeline / UI · 2026-07-17
**Feedback:** Basic math operations cannot be executed in group and summarise, like ATE by taking the difference in means between treatment and control group  
**File:** `src/ExplorerModule.jsx` (line 1779 — `FN_OPTS`; line 1825 — `SQL_AGG`), `src/pipeline/runner.js` (line 528 — `group_summarize`)  
**Suggestion:** `FN_OPTS` and `SQL_AGG` only offer single-column reductions: mean, median, sum, count, min, max, sd. Computing ATE = `mean(Y | T=1) − mean(Y | T=0)` requires either (a) a post-summarize `mutate` on a pivoted result, or (b) a two-row pivot-to-wide followed by subtraction. The most targeted fix is to add a `diff` aggregation type to `SQL_AGG` that computes `SUM(CASE WHEN <treatCol>=1 THEN y ELSE 0 END) / NULLIF(COUNT(*) FILTER(WHERE <treatCol>=1), 0) - SUM(CASE WHEN <treatCol>=0 THEN y ELSE 0 END) / NULLIF(COUNT(*) FILTER(WHERE <treatCol>=0), 0)` — but this requires specifying a treatment column, which `group_summarize` does not currently support per-aggregation. A simpler near-term fix: add a `group_summarize`-then-`pivot_wider`-then-`mutate` guided workflow note in the UI, and/or expose a `diff (two-group)` option in `FN_OPTS` that asks for a binary group column in addition to the value column. The runner `group_summarize` case (line 528) would need to handle the new `fn: "diff"` branch.  
**Invariants:** `runner.js` is pipeline-only pure JS; no React. Registry (`registry.js`) must stay in sync if any new step type is added. Prefer extending the existing `group_summarize` case over adding a new step type.
