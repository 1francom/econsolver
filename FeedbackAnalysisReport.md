**Feedback:** Big datasets generate crashes (21MB) over 900k rows.
**File:** `src/DataStudio.jsx` (parseFile branches for non-DuckDB formats), `src/services/data/duckdb.js`
**Suggestion:** DuckDB routing is already wired for CSV/TSV/Parquet/`.dta` above 10MB. The gap is `.rds`, `.RData`, `.xlsx`, and `.shp` — these are parsed entirely in the browser JS heap (no DuckDB path), so a 21MB RDS or large Excel loads as a full JS array and triggers GC pressure or OOM. For `.xlsx`, SheetJS already parses in JS — after parsing, if `rows.length > 10000`, run `INSERT INTO duckdb FROM VALUES (…)` in batches of 5000 and switch to DuckDB mode, matching the `.dta` path added in `BugTriage 2026-06-10`. For `.rds`/`.RData`, `sexpToTable` returns a plain array — pass it through the same `duckdb.registerTable` call. This is the single highest-ROI remaining perf item since the `.dta` fix already proved the pattern.
**Invariants:** OPFS cache must be used for large files (DuckDB performance strategy rule 3). `_duckdb` must be forwarded in `onComplete` (the bug from BugTriage 2026-07-02 must not recur).
